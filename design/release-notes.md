# 通讯助手 0.4.1 测试版 · 连接探测与验收修复

本版修复隔离验收中首次通信探测的错误路径，以及演示模式缺失原消息时的提示。PKG、DMG、ZIP、使用说明及校验清单同步发布；四项工作台功能保持不变。

## 修复内容

原冒烟脚本每 50 毫秒尝试一次、共 100 次，等待耗尽后没有检查是否连接成功，仍继续写入请求。在本机 macOS 上，未连接的 Unix socket 写入会超时。延迟 6 秒启动演示引擎可复现相同错误；修复后等到连接成功才发请求，10 秒截止前可继续等待。超过期限或子进程提前退出时明确失败，不把未连接误报成业务请求写入超时。性能探测使用相同的连接等待逻辑，每次失败关闭旧连接再重试。

原始偶发事件未记录启动阶段耗时，不能据此确认当时为何启动变慢；本次确认并修复的是可重复复现的探测缺口，未更改工作账号的连接、发送或恢复策略。

演示模式查看未归档的原消息时，明确提示“演示数据中没有这条原消息；演示模式不会联网读取”；本地已有消息正常定位。

## 验收与运行边界

205 项 Python 回归、42 项原生状态检查通过；覆盖模板修改和重开保存、不同任务排队隔离、选择性恢复、恢复失败不部分开启，以及延迟启动、等待耗尽、拒绝连接和提前退出。新包还检查独立演示通信、PKG 载荷、DMG/ZIP 完整性和临时签名。演示或模拟结果不代表真实 Telegram 交付。

**本机继续运行 0.4.0 构建 13，未安装本版。原账号和自动回复保持原配置，原 72 小时观察不中断**，预计 2026-10-18 12:06（北京时间）到期，尚未通过。**0.4.1 未开展独立 72 小时观察，也未进行工作账号真实升级验收**，不能沿用 0.4.0 的观察结果。

## 使用与下载

多任务管理、任务结果中心、跨账号总览、首次使用与恢复向导的操作不变。升级需要退出旧应用，确认身份并选择恢复原有任务；此次发布不会自动更新本机正在运行的应用。

首选 PKG 安装向导，DMG/ZIP 备用。当前仍使用官方 TEST ONLY API，应用临时签名、安装器未签名且未公证。正式 API、签名公证、干净旧系统及完整可访问性仍待完成。固定回复显示“登记未核实”时不能当作考勤成功。
