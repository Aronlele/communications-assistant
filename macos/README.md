# 即讯（原通讯助手） · macOS 内部使用版

当前公开发布版本 **0.6.1 测试版（构建 18）**，支持 Apple Silicon，声明最低 macOS 14；实际本机验收环境为 macOS 27.0.1，干净 macOS 14 尚未验收。Python/Docker 参考实现仍保留在根目录，macOS 产品位于 `macos/`。源码、构建与发布入口见根目录 README。

本版已完成 251 项 Python 回归、82 项原生状态检查、隔离界面、迁移副本和打包引擎验收。本轮用户已取消 72 小时观察及自动复查，长期稳定性保持未验证；实际升级、任务恢复及旧记录补全结果以仓库 `design/acceptance.md` 为准。旧版本观察不拼接为本版通过。

### 0.6.1：群组系统消息与旧空记录

- 新归档将入群/邀请、退出/移除、群组改名和头像变化、创建、置顶、群升级、通话、自动删除设置、话题变更等系统事件保存为可搜索说明；未知事件明确标注暂未支持，身份资料缺失时使用成员ID，不猜造名称。名称为读取时可见资料，不保证是历史名称。
- 实时与历史补档都支持系统事件；只处理用户已选择归档的群组，不进入自动回复路径。仍无法保证平台未提供或已删除事件的完整性。
- 旧空记录显示“无文字内容 · 类型未记录，可尝试补全”，图片无说明单独提示，不再拼出空方括号；真正发送的“[]”原文保持不变。
- 归档页先选择左侧某个群组，再点“检查旧空记录”。预览仅读本地，确认前可取消；确认后按原消息编号、会话和日期读取，每批最多100条，只补可确认的系统事件。可点“下一批预览”，不会自动循环。已删除/不可访问/其他类型/受保护内容保持原样并报告数量；平台限流或网络失败需稍后重新预览，不自动重试。
- 补全保留账号、归档开关、历史游标、任务与发送账本；在途修改或删除会使预览失效，归档暂停/容量受限或正在补档时不执行。数据库仍为schema5，说明保存于原有消息字段，可搜索、导出和备份，无额外数据库迁移。
- 旧记录能否补全取决于平台是否仍返回原消息。预览数量不是恢复数量，须以应用实际处理结果为准；已删除或无法访问的消息不能凭空还原。

### 0.6.0 四项新增能力

0.6.0 构建17新增的以下能力继续保留。验收记录区分独立测试与真实使用，不沿用旧版结果。

- 新建任务改为四步向导：对象、完整提示、固定回复或动态关键词、验证与保存。高级结构可展开配置。保存新任务仍关闭发送，须在列表核对固定身份并开启。全文失败显示首个不同的行列、空格/换行等；不会放宽实际匹配。
- 设置中的“网络诊断与代理”支持每账号直连、SOCKS5、HTTP CONNECT；代理需由用户自己提供，不支持MTProto。密码仅保存到钥匙串，相同地址留空保留密码，换地址需重填。保存只供下次连接，立即重连会短暂停止当前账号并要求恢复原任务。链路探测不创建登录会话，不代表API或登录成功，不改变当前工作连接。
- “检查更新与安全升级”从固定官方仓库获取发布记录，可选择测试渠道。完整下载经长度和SHA256验证，并显示系统安装器信任检查结果。升级前列出账号/任务并备份全部资料、旧应用与偏好；此完整回退副本包含登录会话，仅存本机受保护目录，勿分享。失败时保留原应用，用户确认后才打开系统安装器并退出；安装后仍须核对身份并恢复原任务。尚未完成正式签名公证的测试包会明确提示，不会自动安装。
- “恢复保留的账号资料”查找本应用移除入口留下的目录，预览身份与条数后挂回原入口，不与其他身份合并、不自动开启发送。重复身份、损坏或变化目录拒绝恢复。
- “加密备份”生成.jixunbackup，采用AES-256-GCM与固定参数scrypt密码派生。至少10字符，密码不保存、遗失无法恢复。解锁预览和恢复均验证认证标签，错误密码或篡改不会暂停或修改工作任务；正确恢复后关闭发送。仍支持原ZIP明文备份；业务备份不含登录会话、API或代理密码，网络配置沿用当前入口，需按需重新设置。应用数据库和登录会话本身未因此加密。

### 0.5.0 四项新增能力

- 聊天归档：勾选或右键单条消息，在“清理本地记录”中清理选中内容、当前筛选或当前会话；先预览账号、条数与图片占用，再输入“删除”确认。也可仅清理已保存图片。会话清空可选择保留原归档开关或停止归档。不可撤销、不删除平台消息、不清除发送账本；应用自动迁移快照会清理对应内容，外部另存备份不受影响。删除标记防止已清理内容由补档或业务备份合并重新出现。单次筛选清理最多 10000 条，超过时缩小会话或日期范围。
- 任务管理：从编号查岗、固定回复或自定义关键词模板新建；“更多”可复制关闭的副本或导出 JSON 模板。导入先生成草稿，目标清空，需重新选择并确认；不会导入账号、凭据或发送授权。样例和匹配内容可能包含个人信息，分享前请核对。
- 多样例：编辑任务时最多保存 20 条正反样例，整组总长限 8000 字符，可填写准确预期回复；至少一条正样例，全部通过后才能重新开启。验证草稿不发送消息、不改变其他任务。仅修改样例不会停掉正在运行的任务，但后续重新开启仍须验证通过。
- 异常处理：工具栏和任务结果提供统一入口，解释连接、限流、存储、暂停、待恢复和待核对结果，跳转对应处理页面并支持预览诊断。不会自动解除暂停、恢复发送或重试未知结果。

本版数据库升级为 schema 5，保留迁移前快照并兼容旧业务备份；旧版不能直接打开新版数据，升级前保留完整备份。

## 推荐安装方式

双击 PKG 安装包，按“继续 → 安装”完成安装，从“应用程序”打开即讯。系统可能要求管理员验证。应用展示名为“即讯”，为兼容旧安装，磁盘位置仍固定为 `/Applications/通讯助手.app`；应用标识、钥匙串服务、偏好设置和资料目录继续沿用旧值，无需迁移或重新创建账号。安装器只替换应用，不修改账号、登录会话、归档、规则和发送账本。升级前请正常退出应用，单纯关闭窗口仍会在菜单栏运行。升级后确认账号，再在“准备与恢复”中核对并恢复选中的原有任务。

DMG/ZIP 继续作为备用。当前 PKG 未签名、未公证，应用为临时签名且使用官方测试 API；这是测试交付，不代表已完成正式发行或干净新 Mac 安装验收。无需关闭系统安全保护。

## 使用

推荐下载 Release 中的 PKG 安装向导；DMG 可拖入“应用程序”，ZIP 为备用。应用自带 Python、Telethon 与消息引擎，使用者不需要安装 Python 或 Docker。

1. 本次内部测试包内置 Telegram 官方 TEST ONLY 配置，首次启动直接点击“登录 Telegram”，普通使用者无需申请 API。开发者自己的产品 API 尚未申请成功，该测试配置不能作为正式公开发布的配置。旧版本已保存的自定义配置继续保留。
2. 选择国家区号后输入手机号，或粘贴以 + 开头的完整国际号码；按 Telegram 的实际流程输入验证码、二次验证密码。验证码有重发倒计时，错误或过期时按提示恢复。
3. 确认界面上的账号身份。验证码和密码不保存。登录中可以取消，再重新开始。
4. “消息提醒”里测试系统通知权限，按需开启语音、通知声音和正文预览。语音默认关闭，默认只播报来源；可选读正文、按周静音时段和每个会话的提醒方式。静音不暂停自动回复。
5. “聊天归档”选择私聊或群组，选择最近 300 条、仅新消息、或指定起始日期。频道暂不支持。
6. “任务管理”新建任务，选择机器人或明确允许的普通联系人，配置关键词或固定回复方式，保存并验证样例，再确认固定目标和实际回复内容后开启。发送测试消息需单独核对目标与文本。仅支持直接私聊，不能绑定本人；每次重启、恢复身份或修改规则后都需要重新启用。

也可以先点“体验本地演示”，无需账号即可浏览产品页面。演示数据存放在独立目录，不连接 Telegram，自动发送不可开启；可从菜单栏或设置返回真实账号登录。

“设置 → 高级设置 → Telegram 连接配置”可选择产品内置配置或自定义 API。未登录时也能打开设置。自定义 API Hash 保存到 macOS 钥匙串，编辑时留空可以保持同一个 API ID 的原值；修改 ID 时必须重新填写 Hash。保存后返回登录页使用。已登录、连接进行中或演示模式不能修改配置，请先退出账号或取消登录。清除自定义配置会恢复产品内置配置，保留归档。旧版本已保存的 API 自动识别为自定义配置，不会被新内置配置悄悄替换。

关闭窗口会继续在菜单栏运行；按 ⌘Q 退出会停止引擎。合盖、睡眠、网络不可用时不能实时执行，恢复连接后会尝试补齐归档。网络恢复期间的有效新提示可继续处理，重启前的旧提示不补发。

没有网络时可以切换已保存账号，分别浏览其本地归档。正常运行需要这台 Mac 可以直接访问 Telegram；可在设置中按账号配置SOCKS5或HTTP CONNECT代理；系统网络环境仍可继续使用。

## 多账号同时使用（0.3.0）

左下角显示当前账号的 Telegram 头像、名称和连接状态。点击它可切换账号或选择“添加 Telegram 账号…”，无需退出已登录账号。头像加载失败或账号没有头像时显示姓名首字，下次登录时重新获取。

每个账号独立登录和确认身份，拥有完整的提醒、语音、静音时段、归档、图片、搜索、导出、旧记录导入、备份恢复、查岗自动回复、登记回执、在线策略、设备信息和诊断。切换页面只改变正在查看的账号，其他账号继续接收消息和执行原有规则。不能重复添加同一个 Telegram 账号。

左下角点击账号名称，选择“移除当前账号…”。已登录账号需先在设置中退出，登录过程可先取消；确认后仅移除登录入口，本地归档、规则、发送账本和自定义配置仍保留，其他账号继续运行。至少保留一个登录入口。重新添加不会自动合并旧归档；可在设置中“恢复保留的账号资料”挂回原入口，或从业务备份恢复。

页面中的暂停、退出、删除数据、备份和恢复仅作用于当前账号。自定义 API 配置也按登录入口隔离；新增账号默认使用内置配置。登录启动、防空闲睡眠和 macOS 系统通知权限属于整款应用，所有账号共用。

通知和语音包含来源账号名称。点击后台账号的通知会自动切换到对应账号，再打开指定消息；该账号未连接或尚未确认身份时先完成登录，随后再定位。切换账号会清空当前搜索、模板预览、待恢复文件和登录输入，避免将旧账号操作应用到新账号。

验证码重发使用当前登录入口已经提交的手机号，切换账号后无需重新填写旧入口的号码。

退出整款应用会停止全部账号。应用重启或引擎恢复后，各个已保存账号分别恢复连接，需要逐个确认身份、按需重新开启自动回复；不会自动补发重启前的查岗。查看某个账号不影响其他账号已开启的自动回复。

旧账号的数据和 Telegram 会话仍在原目录。新增登录入口保存到 `~/Library/Application Support/通讯助手/accounts/<随机标识>/`，各自独立数据库、会话、头像和图片；`accounts.json` 仅保存登录入口和当前选择，不保存凭据。旧归档和发送账本无需迁移。

## 多任务、结果与恢复（0.4.0）

- “任务管理 → 新建任务”：命名、选择对象、设置匹配和回复、有效期、优先级及每周时段。所有账号和原有规则保留，旧规则原位显示为“原有回复任务”。编辑一个任务不会关闭其他任务。
- “从提示提取关键词”默认兼容原查岗结构。编号、称呼、关键词和分钟数可以变化；例如编号 00176、关键词“香蕉”、20 分钟，无需把香蕉保存为固定回复。
- 要改变识别结构，开启“自定义提取模板”，使用各一个 `{number}`、`{minutes}`、`{keyword}`，关键词占位符单独一行；可选 `{name}`。其余文字与换行精确匹配，可从标准查岗样例生成后编辑。
- “测试样例”和“匹配模板”用途不同，两者都会保存。先预览草稿，再“保存任务并验证样例”；重新打开可继续编辑。只改名称或样例保留启用状态，改变对象、回复、优先级或时段后该任务恢复仅提醒。成功预览不是开启发送，还需确认固定身份。
- 多条已开启任务同时匹配时只执行优先任务（优先级数值大者优先，相同按列表顺序）；仅提醒任务不阻挡已开启任务。来源消息和原编号账本共同防重，切换回复方式、删任务或重启均不自动重试已提交请求。
- “任务结果”：按任务、结果或“需要关注”筛选，50 条分页，区分仅提醒、跳过、发送中、已发送、回执确认、结果未知和过期，可定位原消息或打开 Telegram 会话。删除任务不删除账本，已有编号的迟到回执仍可确认。
- “所有账号”：同时查看各账号连接、任务数量、待恢复、暂停、限流、归档受阻及待核对结果，从卡片进入对应账号。未登录的空入口不算掉线。
- “准备与恢复”：首次准备逐项检查身份、通知、归档、任务和后台运行；可以暂不启用任何功能。重启后保留此前开启意图，核对身份后勾选恢复，一次确认选中任务；手动关闭的任务保持关闭，不补发旧提示，不解除账号原有暂停。
- 当前数据库为 schema 5，升级前保存迁移快照，账号目录不移动；业务备份兼容 schema 3/4/5，旧备份先在临时副本升级，不改原备份文件。恢复关闭全部任务并要求重新预览。回退旧应用前须先恢复完整的升级前资料，不能让旧版直接读取 schema 5。

安装包内帮助为构建时快照；仓库和 Release 中的使用说明附件持续记录本次版本的功能与限制。长期观察不能由离线测试替代。

## 已实现的功能

### 自定义提示与固定回复（0.3.1）

在当前账号的“任务管理”页面新建或编辑任务，填写机器人或联系人用户名、数字 ID，保存为仅提醒。普通联系人需明确开启“允许选择普通联系人”；仅支持与该对象的直接私聊，不能绑定本人。

在“回复方式”选择“匹配提示，固定回复”，填写完整提示和要发送的单行内容，例如提示“📣 管理员正在进行在线抽查，请回复任意内容确认在岗。”、回复“1”。默认“全文相同”，只忽略首尾空白和换行格式；可主动选择“包含指定文本”，扩大匹配范围。不执行正则或脚本。

本地回复有效期默认 5 分钟，可设 1–1440 分钟，从消息发出时间计算，防止迟到的旧消息触发回复；这不是从机器人提示提取的业务时限。保存后恢复仅提醒并清除原预览，粘贴一条实际提示，点击“保存任务并验证样例”，检查将发送的内容，再确认开启。未保存修改不会改变正在执行的规则。

固定回复按账号、目标、来源消息 ID 永久去重；同一条消息只尝试一次，机器人重新发送的新消息视为新的抽查。转发、群消息、本人发出的消息、旧消息及超过本地有效期的消息不回复，暂停及允许发送时段继续生效。没有提供可可靠关联的回执格式时，显示“已发送，登记未核实”，不猜测登记成功或触发编号回执超时提醒。

现有“从查岗提示提取关键词”方式保持兼容。0.4.0 每个账号可配置多个对象和最多 50 个任务；每条任务单独选择回复方式和时段，修改执行条件后仅暂停该任务，重新预览并确认后启用。已有编号发送的同编号回执仍继续核对。

- 原生 SwiftUI 窗口，九个页面、菜单栏面板、快捷键、浅色/深色系统外观。
- 图形化 Telegram 个人账号登录、二次验证、身份确认、远端退出尝试；不同账号的数据和规则隔离。
- 私聊和提及提醒、免打扰会话、按周静音、会话单独设置、通知声音和语音正文开关、同一会话 10 秒合并、暂停提醒 30 分钟。通知可定位对应消息；语音队列有上限、过期摘要和播放结果活动记录。

## 数据与凭据

实际账号的数据：`~/Library/Application Support/通讯助手/`。演示数据使用独立目录 `~/Library/Application Support/通讯助手演示/`，不会连接网络或发送消息。

目录权限 0700，数据库和 Telegram 会话文件权限 0600。SQLite 与 Telethon 会话未额外加密，需要保护 macOS 登录账号与磁盘。各登录入口使用独立数据库，所有查询继续强制按账号过滤。图片按账号/会话隔离。

发送编号及结果状态会保留到删除账号数据为止；关键词、聊天内容和活动日志按保留期清理。清除聊天归档不清除防重复账本。删除账号数据会清除账本，之后不能保证对历史编号去重。

退出账号会尝试撤销 Telegram 远端会话，再删除本地会话。界面明确说明远端撤销是否确认，失败时请在 Telegram 的“设备”中核对。已有归档默认保留。自定义 API 配置可以在未登录时的高级设置清除。

卸载应用不会自动删除本地数据或钥匙串项目。建议先在应用内退出账号、按需要删除账号数据并清除 API 配置，再移除应用。Telegram 的远端设备管理是最终核对入口。

## 构建与测试

需要 macOS、Apple Command Line Tools（Swift）、Python 3.13。依赖版本固定在 `requirements-build.txt`。构建仅下载公开构建依赖，不读取旧项目 `.env`、聊天记录或真实 session。

```sh
bash macos/scripts/build.sh
PYTHONPATH=macos:. macos/build/venv/bin/python -m unittest discover -s macos/tests -v
macos/build/venv/bin/python -m unittest discover -s tests -v
python3 macos/scripts/smoke.py output/macos/通讯助手.app/Contents/Resources/Engine/tgengine

```

PyInstaller 使用文件夹模式内置运行时。Swift 原生程序通过本地 Unix socket 使用版本化 JSON 协议，只有消息引擎写数据库。App 自己拥有子进程生命周期，socket 不监听网络端口，权限 0600。

主要源码：`Sources/App.swift`（应用生命周期）、`Sources/Views.swift`（界面）、`Sources/Model.swift`（界面状态、钥匙串、通知、语音、本地通信）、`engine/service.py`（账号、平台事件与功能编排）、`engine/store.py`（持久化与账本）、`engine/automation.py`（自动回复）、`engine/schedule.py`（时间边界）。固定消息模板沿用根目录 `auto_checkin.py` 的严格解析。

## 产品 API 打包配置

成功申请后将开发者配置保存到 `macos/Private/TelegramAPI.json`（该目录已忽略），或通过 `TGA_API_CONFIG` 指定本地文件。JSON 只需要数字 `api_id` 和字符串 `api_hash` 两个字段。不要把真实配置提交到代码仓库。构建工具不扫描旧 `.env` 或聊天会话，也不打印凭据。

```sh
TGA_API_CONFIG=/绝对路径/TelegramAPI.json TGA_RELEASE=1 bash macos/scripts/build.sh
```

`TGA_RELEASE=1` 要求配置存在且格式有效；缺失或无效会在构建开始时停止。它只校验格式，不证明凭据已获 Telegram 接受，也不代替 Developer ID 签名、公证和真实登录验收。普通开发构建可以不提供配置，此时应用明确显示待配置状态。

构建会将配置放入签名前的应用资源 `TelegramAPI.json`，并清除复用构建目录和旧产物中的过期配置。API 配置随桌面产品分发，可以被本机使用者提取；不能把它当作服务器私密密钥。它标识应用，不包含用户登录会话或密码。无需为此额外部署凭据分发服务器。

## 验收边界

离线测试不证明真实 Telegram 登录、收发、在线展示或限流表现。演示模式不模拟这些结果为真实成功。真实账号基础登录、归档、通知中心、专用测试机器人自动回复与回执已在 0.1.2 联调通过；0.2.0 的逐项结果见 ACCEPTANCE.md。72 小时结果与干净的 macOS 14 机器验收不能由离线测试替代。

设备信息在“设置 → 高级设置 → Telegram 设备信息”中调整。支持设备名称、系统版本和客户端显示版本；保存供下次连接使用，或立即重新连接。后者保留归档和账本，但需要确认账号与重新启用自动回复。可读取平台当前会话实际显示值。应用名称由 API 标识决定，地区由网络出口决定。

当前为公开下载的测试包，应用使用临时签名，安装器未签名、未公证，尚不满足面向普通用户正式推广的条件。设置中可主动检查官方更新，校验下载并备份后由系统安装器升级，不会静默替换应用。不包含付费、多人协作、云端数据或 Intel 包。

平台未投递的删除/编辑事件无法保证同步，导出的历史范围不意味着平台记录完整。旧图片仅迁移 TXT 引用且位于所选文件相邻 media 目录中的有效图片，不扫描其他目录。容量计算是当前账号的文字与媒体估算，不等同于整个 SQLite 文件的物理大小。语音使用系统中文声音；不含自定义声音和多轮重复播报。

备份为未额外加密的本地 ZIP（界面默认扩展名 .zip），可包含聊天正文和图片，请保存在受保护的位置。它不包含 Telegram session、API 凭据、验证码和密码。恢复只接受当前账号的备份，合并消息及发送编号，保留已有消息版本，不回滚删除或已确认账本；不会恢复登录。

质量检查脚本 quality.py 使用临时合成数据；endurance.py 只读取不含身份与正文的 runtime-status.json 和进程资源，不接入引擎 socket。长时间记录里设备睡眠、退出及观察中断需要单独解释，不能自动认定验收成功。
